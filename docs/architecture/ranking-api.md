# 권역 랭킹 조회

[백엔드 랭킹 계약](https://github.com/sugkamoney/geupjido-backend/blob/main/docs/architecture/ranking-tab-api.md)과 [고정 OpenAPI](api/openapi-2026-11-20.json)를 기준으로 같은 출처의 `GET /api/v1/rankings/zones`를 호출한다. 데스크톱과 모바일 웹에 같은 읽기 계층을 사용한다.

- 기본 필터는 `ALL / GRADE_1 / CURRENT`다. `COLLECTING`의 요청과 쿼리 키에는 항상 `CURRENT`를 적용한다. 필터 UI도 탭 전환 시 선택 상태를 `CURRENT`로 갱신한다.
- 런타임 검증은 생성 타입에서 선택 필드로 표시한 응답 필드의 존재와 타입을 확인한다. 두 발행 시각과 권역의 `tier`, `rank`, `previousTier`, `tierDelta`는 명시적인 `null`을 허용한다. 소수 급지와 발행 시각 원문을 보존한다. 날짜가 유효한지, 변동 폭이 음수가 아닌지, 1~5급지 개수가 각각 한 번씩 제공되는지 확인한다. 응답 필터가 요청에 적용한 필터와 다르면 해당 쿼리를 계약 오류로 처리한다.
- 권역명과 배열 순서, 지역 범위의 `rank`와 `rankTotal`은 서버 값을 사용한다. 탭 또는 정렬을 변경해도 목록 길이로 순위 분모를 다시 계산하지 않는다. 유효표, 참여자, 교차 권역 투표 집계는 마지막 발행 기준이다.
- 브라우저 요청은 `no-store`를 사용한다. TanStack Query는 적용한 세 필터를 키에 포함하고 필터별 응답을 관리한다. 조회 함수에 취소 신호를 전달하며 앞선 요청이 늦게 끝나도 현재 필터 결과에 반영되지 않는다.
- 빈 배열은 정상 결과다. HTTP 실패는 `RankingApiError`, 응답 계약 위반은 `RankingContractError`로 구분한다. 훅은 오류를 즉시 노출하고 `refetch()`로 재시도한다.

## 패널과 지도 선택 연결

실서비스 지도 탐색 페이지가 지역·급지·정렬 상태를 소유한다. 기존 `QueryClientProvider` 아래에서 앱 셸이 랭킹 슬롯을 렌더링할 때 `RankingContent`가 `useRankingZones`를 호출한다. 슬롯을 닫아도 페이지에 필터가 남는다. 순수 지도 픽스처 경로에서는 랭킹 슬롯을 제공하지 않는다.

탐색 페이지는 셸에 `ranking?: (context: { signal: AbortSignal; onZoneSelected: () => void }) => ReactNode`를 전달한다. 셸은 패널 닫기, 메뉴 전환, 컴팩트 레이아웃 변경과 unmount에서 해당 구간의 신호를 취소한다. 탐색 페이지는 유효한 상세 응답을 지도와 상세에 적용한 뒤 성공 콜백을 호출한다. 데스크톱에서 두 패널 유지, 모바일에서 랭킹 닫기, 상세 포커스는 셸이 처리한다.

랭킹 행의 `zoneId`로 기존 `GET /api/v1/map/zones/{zoneId}`를 호출한다. 화면에 없는 권역도 조회할 수 있다. 응답의 권역 ID와 단지 소속을 확인하고 단지 ID 중복을 제거한다. 상세의 중심점으로 기존 라벨 선택 동작을 실행하고 같은 응답의 경계와 단지 목록을 상세 훅에 건네 재요청을 피한다. 요청 실패 또는 불일치 시 기존 지도 선택을 유지하고 랭킹 안에서 해당 권역을 재시도한다.

랭킹과 라이브 타임라인은 하나의 권역 이동 요청을 공유한다. 새 권역 선택, 검색 입력 및 결과 선택, 지도 선택·명령·제스처, 상세 닫기, 랭킹 필터 변경이 앞선 이동을 취소한다. 취소를 무시하는 소스에도 응답 적용 직전에 구간 신호와 이동 요청 신호를 검사한다. 지도 카메라 애니메이션과 프레임 변화는 직접 입력으로 취급하지 않는다.

테스트 셸은 실제 랭킹·지도 GET 클라이언트와 픽스처 지도 어댑터를 사용한다. 셸을 합친 데스크톱·모바일 브라우저의 포커스와 패널 전환은 별도로 확인한다.
