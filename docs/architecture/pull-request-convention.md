# PR 작성 규칙

- 상태: 확정
- 최종 수정일: 2026-10-13

PR은 [기본 템플릿](../../.github/pull_request_template.md)을 사용한다.
변경 내용과 이유, AI 코드 작업 여부, 테스트 케이스만 간결하게 기록한다.

## 제목

`[#이슈번호] category: 한글 요약` 형식으로 작성한다.
이슈가 없으면 `[#이슈번호]`를 생략한다. category는 커밋과 동일하게
`docs`, `feature(web)`, `bugfix` 중에서 선택한다.

PR 제목과 커밋 메시지에는 이모지를 사용하지 않는다.
PR 본문의 섹션 제목에는 이모지를 사용할 수 있다.

예: `[#12] feature(web): 지도 검색 기능 추가`

## AI 코드 작업과 검증

코드 작성·수정은 100% AI로 진행하고 PR 본문의 체크 항목에 표시한다.
문서만 변경한 경우에는 `해당 없음 — 문서 변경만 포함`으로 작성한다.

테스트 케이스에는 시나리오 또는 실행 명령, 기대 결과, 실제 결과를 기록한다.
자동 테스트와 수동 확인을 모두 사용할 수 있으며, 실행하지 않았다면 이유를
명시한다. 테스트가 해당 없으면 그 근거를 작성한다.

화면 변경은 데스크톱과 모바일 웹의 확인 결과를 포함한다. 모바일 웹 지원이
제한되거나 연기된 경우에는 해당 범위를 명시한다.
