# 지도 연동 마무리와 검증

> 상태: FE 구현·자동 검증·실제 SDK/API smoke 완료 · 버전: 1.0 · 갱신: 2026-11-20

## 결과와 범위

`origin/develop`을 작업 브랜치에 통합하며 기존 문서 커밋도 보존했다.
FE만 수정했다. 구현·검증 후 사용자 요청에 따라 변경을 커밋하고 `develop` 대상 PR로 제출한다. 공유 브랜치 merge와 배포는 별도다.

- viewport와 독립된 선택 권역 snapshot을 유지한다. 상세 지연·실패에도 이름·급지·라벨을 유지하며 최신 상세가 우선한다. 닫기·구/다른 권역 전환은 이전 선택을 정리한다.
- 검색 이름의 직접 일치를 먼저 강조하고 구+권역 복합 강조도 유지한다.
- 배포된 `areaSquareMeters`를 실측 ㎡ 그대로 라벨 충돌의 선택→큰 면적 순에 연결한다. 예시 상대 가중치를 실측 면적으로 해석하지 않는다.
- 상세 단지 `location`을 직접 사용한다. bbox 추가 핀 요청·임시 위치 조회 실패 UI를 제거했다. null 단지 목록·선택, 이미 확보한 선택 좌표, 수동 목록 스크롤을 유지한다.
- 고정 OpenAPI와 생성 타입을 연결했다. 필수 필드·유한 숫자·좌표·null·geometry 런타임 검증은 유지한다.

구조는 [화면 연결](map-api-ui-integration.md), [읽기 계약](map-api-read-layer.md),
판단 이유는 [ADR-008 재검토](../history/ADR-008-map-api-first-integration.md#2026-11-20-재검토-결과)를 따른다.
Figma `03 Screens`(82:5)의 구/권역/선택 화면 구조를 다시 확인했다. 이번 작업은 기존 화면의
데이터·선택 연결이며 전체 디자인 또는 모바일 작업공간의 최종 승인을 의미하지 않는다.

## 검증 근거

Node 24.15.0 / pnpm 11.13.0을 사용했다. 명령은
`npx --yes --package=node@24.15.0 --package=pnpm@11.13.0 -- pnpm …`으로 실행했다.

E2E 첫 실행은 128 통과·3 실패·34 제외였다. 기존 합성 상세의 location:null인데 목록 클릭으로
이동을 기대한 테스트 데이터가 원인이었다. 위치가 있는 시나리오는 상세 location을 제공하도록
수정했고, null 시나리오는 별도로 유지했다. 변경 E2E 15건 및 전체 131건 재실행이 통과했다.
개발 API 쓰기·가상 투표는 수행하지 않았다.

## 검증 한계와 후속

- 물리 iPhone/Android의 실제 gesture·OS 키보드·주소창·접근성은 이번 세션에서 미검증이다. 모바일 웹은 지원하며 이번 검증은 브라우저 에뮬레이션이다.
- 실제 SDK smoke는 위 선택 흐름만 검증했다. 전체 터치 제스처·핀치·저속 네트워크·장시간 성능을 이번에 다시 검증한 것은 아니다. 기존 엔진별 기록은 [경계·모바일 검증](map-boundary-mobile-validation.md)을 따른다.
- 내장 브라우저가 `iab` 연결 불가여서 저장소 Playwright의 실제 SDK+API 브라우저 확인으로 진행했다. 부모 작업공간에 있던 키는 서버 프로세스에만 전달했고 파일·출력·문서에 노출하지 않았다.
- 한강 수면 제외는 BE geometry 후속이다. 이번 실제 압구정 응답도 MultiPolygon 1개 면이며 FE에서 위도 절단·임의 보정하지 않았다. [BE 요청 초안](map-boundary-backend-followup.md)은 미발송이다.
- 상태 카드·민심 전환·랭킹·리포트·월드컵 API와 브랜드 변경은 범위 밖이다. 이번 검증은 전체 제품 완료나 모든 실제 지역의 지리 정확성을 보장하지 않는다.
