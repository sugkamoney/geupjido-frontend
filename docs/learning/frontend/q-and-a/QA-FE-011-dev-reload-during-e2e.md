# QA-FE-011: 실행 화면이 E2E 중 새로고침되는 이유는 무엇인가?

> 날짜: 2026-11-20 · 성격: 급지도 개발 서버와 테스트 빌드의 간섭 진단

## 질문

월드컵 실행 화면에서 종종 새로고침처럼 느껴지는 현상이 있다. 구현·검증이 모두 끝났다는 의미와 실제 새로고침 원인은 어떻게 구별하는가?

## 핵심 답변

자동 검사는 명시된 시나리오의 통과를 증명한다. 실제 서버 저장·쿠키·기기 조합까지 전부 검증한 뜻은 아니다. 전체 페이지의 문서 재탐색과 React 재렌더링, API 재조회, 개발 서버의 변경 반영을 구분해 원인을 확인해야 한다.

Vite 개발 서버는 파일 변경을 감시한다. 컴포넌트나 CSS는 HMR로 갱신할 수 있고 HTML 변경은 전체 새로고침 신호를 보낼 수 있다. 같은 저장소 안에 생성된 테스트 HTML도 제외하지 않으면 이 감시에 들어갈 수 있다. Git에서 무시되는 파일이라고 개발 서버에서도 반드시 무시되는 것은 아니다. [Vite server.watch](https://vite.dev/config/server-options.html#server-watch)에서 감시 제외를 지정한다.

## 이 프로젝트의 적용

실행 중인 Vite 로그에서 E2E 빌드가 `dist-e2e/fixture/index.html`, `dist-e2e/naver-error/index.html`을 만들 때 `page reload`가 반복된 것을 확인했다. 앱의 일반 탐색이 자동으로 새로고침된 것으로 단정하지 않는다.

`vite.config.ts`의 server.watch.ignored에 dist-e2e·test-results·playwright-report를 추가했다. 실제 설정을 불러온 격리 임시 Vite 서버에서 앱 HTML은 전후 양성 대조로 변경 신호를 확인하고, 생성 HTML만 바꿨을 때 새로고침 신호가 수정 전3건에서 수정 후0건으로 줄었음을 검증했다. 사용자 확인 중인 앱을 반복 재시작시키지 않도록 이 재현은 별도 임시 디렉터리에서 수행했다.

실제 소스나 Vite 설정을 수정하면 개발 서버의 갱신·재시작은 여전히 발생할 수 있다. 사용자가 안정적으로 확인해야 할 때는 별도 빌드 산출물을 사용하는 preview를 제공하고, localhost Origin과 실제 API 프록시를 유지한다.

월드컵 진행·타임라인은1분 또는 창 복귀 때 서버를 다시 읽는다. 이는 문서 새로고침과 다르며, 대진을 자동 재시작한다는 뜻도 아니다. 현재 `window.location.reload()`는 지도 오류 화면의 명시적인 다시 시도 동작에 연결돼 있다. 파일 변경이 없는 상태에서도 재탐색이 관찰된다면 브라우저 네트워크·탐색 기록을 확보해 별도 조사한다.
