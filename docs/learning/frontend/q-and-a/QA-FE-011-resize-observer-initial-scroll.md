# QA-FE-011: 크기가 그대로인데 WebKit에서 목록이 맨 위로 돌아간 이유

질문: 단지 선택 뒤 목록을 수동 스크롤하고 지도를 확대했을 때, macOS 검사는 통과하지만
Linux WebKit CI에서는 목록 위치가 500에서 0으로 바뀌는 이유는 무엇인가?

ResizeObserver는 크기가 바뀔 때뿐 아니라 `observe()` 이후 최초 알림도 전달한다.
이 최초 알림은 동기 호출이 아니므로 선택 직후 자동 정렬과 사용자의 수동 스크롤보다
늦게 도착할 수 있다. 알림마다 선택 행을 가운데 맞추면 크기 변화가 없어도 사용자 위치를 덮는다.
알림을 받았다는 사실과 실제 크기가 달라졌다는 사실을 구분해야 한다.

급지도 `ApartmentList`는 선택 직후 자동 정렬을 유지하면서 당시 목록 크기를 보관한다.
관찰 콜백에서는 현재 크기를 비교해 달라질 때만 다시 정렬한다.
데이터 갱신·지연된 최초 알림은 수동 위치를 유지하고, 실제 모바일 시트 크기 변경은 선택 행을 다시 보여준다.
높이 0인 숨김 상태도 기록하므로 재표시 동작을 놓치지 않는다.

Linux의 기존 E2E를 재현하고 실제 콜백·scrollTo를 계측해 원인을 확인했다.
단위 회귀는 같은 크기 알림을 수동 스크롤 뒤에 전달하여 실행 속도와 관계없이 문제를 드러낸다.
대기 시간을 늘리거나 테스트에서 최초 알림이 끝날 때까지 기다리는 것만으로는 제품 결함을 고칠 수 없다.
