# QA-FE-002: 모바일 개발자가 알아야 할 급지도 웹 기술 용어는 무엇인가?

> 날짜: 2026-09-19 · 성격: 모바일 개발 경험을 기준으로 한 웹 용어 설명

## 질문

급지도 프론트엔드 기술 스택 설명에 나온 용어를 모바일 개발자가 이해하기
쉽게 설명하면 어떻게 되는가?

## 핵심 답변

### 웹 애플리케이션 구조

- **SPA**: 최초에 앱 실행 코드와 기본 HTML을 받은 뒤 브라우저 안에서 화면을
  전환하는 방식이다. 하나의 Activity 또는 앱 셸 안에서 여러 화면을 바꾸는
  모바일 앱과 비슷하다.
- **SSR / SSG**: SSR은 요청마다 서버가 초기 HTML을 만들고, SSG는 빌드할 때
  HTML을 미리 만든다. 검색 엔진과 첫 화면 노출에는 유리하지만 지도 중심
  화면은 결국 브라우저에서 동작해야 한다.
- **SEO / OG**: SEO는 검색 결과에 잘 노출되도록 만드는 작업이고, OG는 링크를
  메신저에 공유했을 때 표시되는 제목·설명·이미지 정보다.
- **Vite**: 웹 개발 서버이자 빌드 도구다. 역할만 비교하면 Gradle/Xcode의
  빌드 기능과 빠른 개발용 실행 환경을 합친 것에 가깝다.
- **React Router**: URL과 화면을 연결한다. 모바일의 Navigation Component나
  딥 링크 라우팅과 유사하다.

### 데이터와 API

- **서버 상태**: API에서 받아온 데이터와 로딩·오류·캐시 상태다. TanStack
  Query가 Repository의 네트워크 조회와 메모리 캐시 일부를 맡는 셈이다.
- **URL 상태**: 선택한 지역과 필터를 URL에 담는 것이다. 딥 링크나 navigation
  arguments처럼 새로고침·공유 뒤에도 같은 화면을 복원할 수 있다.
- **OpenAPI / Springdoc**: 백엔드 API의 URL, 파라미터와 응답 형식을 기계가
  읽을 수 있게 설명하는 명세와 그 명세를 생성하는 Spring 도구다.
- **API 타입 생성**: OpenAPI에서 TypeScript 타입을 만든다. Retrofit 모델과
  API 인터페이스를 명세에서 자동 생성하는 것과 비슷하다.
- **MSW**: 브라우저와 테스트에서 HTTP 요청을 가로채 가짜 응답을 반환한다.
  Android의 MockWebServer와 역할이 비슷하다.

### 지도와 공간 데이터

- **GeoJSON**: 점, 선, 폴리곤을 JSON으로 표현하는 표준 형식이다.
- **PostGIS**: PostgreSQL이 위치와 도형을 저장하고 포함·거리·인접 계산을
  수행하게 해주는 확장 기능이다.
- **SRID 4326**: 일반적인 GPS 위도·경도 좌표 체계를 가리키는 번호다.
- **베이스맵 / 타일 / 오버레이**: 베이스맵은 도로와 지명이 보이는 배경,
  타일은 이를 작은 조각으로 나눈 데이터, 오버레이는 그 위에 올리는 급지
  폴리곤이나 단지 마커다.
- **지도 어댑터**: 화면이 NAVER SDK를 직접 사용하지 않게 중간 인터페이스로
  감싼 코드다. 플랫폼 SDK를 Repository나 Wrapper 뒤에 숨기는 방식과 같다.
- **`window.naver`**: 외부 스크립트가 브라우저 전역에 등록한 NAVER Maps SDK
  객체다. React 수명주기에 맞춰 생성하고 이벤트 리스너를 해제해야 한다.

### 웹 환경과 테스트

- **CORS**: 다른 도메인의 API 호출을 브라우저가 허용할지 서버가 선언하는
  보안 규칙이다. 일반 네이티브 앱에는 동일한 브라우저 제한이 없다.
- **리버스 프록시**: 브라우저는 같은 도메인의 `/api`로 요청하고 앞단 서버가
  실제 Spring 서버로 전달하는 구성이다. CORS와 쿠키 처리가 단순해진다.
- **Client ID / Client Secret**: 브라우저의 Client ID는 사용자에게 보일 수
  있으므로 허용 도메인으로 제한한다. Client Secret은 절대 브라우저 번들에
  넣지 않고 백엔드에서만 사용한다.
- **Playwright smoke test**: 실제 브라우저를 자동 조작해 앱의 핵심 경로가
  최소한 동작하는지 확인한다. Espresso/XCUITest의 웹 버전에 가깝다.
- **SSE / WebSocket / polling**: SSE는 서버에서 브라우저로 단방향 스트림,
  WebSocket은 양방향 연결, polling은 일정 주기로 API를 다시 호출하는 방식이다.

## 급지도 프로젝트에 적용되는 방식

급지도는 React 기반 SPA로 시작하고, URL에는 선택한 지역과 필터를 담는다.
서버 데이터는 TanStack Query, 지도 표시는 NAVER Maps 어댑터가 담당한다.
백엔드는 GeoJSON을 공급하고 공간 판정은 PostGIS에서 수행한다. 지도 Client
ID는 등록 도메인으로 제한하며 Secret이 필요한 NAVER REST API는 Spring
백엔드를 통해 호출한다.
