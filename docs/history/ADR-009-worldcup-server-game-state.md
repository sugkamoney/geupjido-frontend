# ADR-009: 월드컵은 서버 게임 진행을 기준으로 재동기화한다

> 상태: 확정 · 날짜: 2026-11-20 · 영역: 프론트엔드

## 맥락

기존 월드컵 UI는 cursor로 한 판씩 만드는 예시 source다. 실제 서버는 고정10판, 같은 익명 쿠키의 최근 게임, 선택·넘김 기록과 nextRoundNumber를 반환한다. 응답 유실이나 다른 탭의 진행 때문에 로컬 cursor만 증가시키면 실제 확정 기록과 달라진다. 생성 OpenAPI에는 required/null 표현도 충분하지 않다.

## 선택지

1. 예시 source의 URL만 교체하고 로컬 cursor를 유지한다. 변경은 작지만 이어하기·충돌·10판 경계를 정확히 표현하지 못한다.
2. 모달 전체를 새로 만든다. 서버 모델은 직접 표현할 수 있지만 기존 focus·IME·모바일·자산 회귀 범위가 크다.
3. 기존 표시 컴포넌트를 재사용하고 실제 게임 상태 hook·검증·transport를 추가한다.

## 결정과 이유

3을 택한다. 서버 nextRoundNumber와 확정 기록이 권위다. 성공한 PUT을 검증한 뒤에만 피드백을 표시한다.409는 새 성공으로 세지 않는다. 불확실한 응답의 재시도는 GET으로 저장 여부부터 확인한다. 일반·권역 API scope와 한국 날짜 경계를 분리한다. 고정 생성 타입은 유지하고 필수/null·진행 불변식은 런타임 검증으로 보강한다.

My Picks는 페이지에서 확인된 선택만 표시하고, 오늘 진행은 서버의 일반 선택+넘김 집계를 별도로 표시한다. 제공되지 않는 과거 전체 개인 이력을 복원한 것처럼 보이지 않게 보존 범위를 안내한다.

## 비용과 재검토

예시와 실제 상태 경계를 함께 유지하므로 테스트가 두 흐름을 다뤄야 한다. game ID/version이 외부에 없어 완전히 같은 snapshot의 서로 다른 게임을 원자적으로 구분할 수는 없다. 다중 탭 게임 교체를 조건부 PUT으로 보장해야 하거나 개인 전체 이력 API가 도입되면 계약·상태 경계를 다시 검토한다. 상세 구조와 검증은 [월드컵 기술 문서](../architecture/worldcup.md)를 따른다.
