# ADR-006: 앱 화면 틀을 데이터 기능과 분리하고 반응형 배치는 검토용으로 유지한다

> 상태: 확정 · 날짜: 2026-10-13 · 영역: 프론트엔드·제품

## 맥락

디자인 시스템 PR #2가 develop에 통합됐다. 실제 지도/제품 API가 없어도
패널 배치·접기/복원·focus·스크롤을 검토해야 한다. 모바일은 정식 지원이지만
HTML 배치와 최소 viewport가 확정되지 않았다. 랭킹·리포트 화면도 없다.

## 선택지

1. SDK/API와 화면 틀을 함께 구현: 실제 탐색을 검증할 수 있으나 이번 승인 범위를 넘는다.
2. 원본의 데모 수치로 제품 화면 구성: 원본과 가깝지만 미정 정책을 사실로 오해할 수 있다.
3. 공통 UI와 데이터 없는 슬롯 조합, 별도 검토 경로: 배치와 상태를 먼저 검증할 수 있다.

## 결정

3을 선택한다. 홈은 준비 상태, `/app-shell`만 검토용 fixture를 제공한다.
선택 상세·검색 콘텐츠·지도 어댑터 동작은 호출자가 공급한다. layout state는
화면 틀이 소유하고 실제 정책·API 계약·집계는 후속 SDD에서 정한다.
랭킹·리포트는 사용자 답변에 따라 검토 화면에만 비활성으로 표시한다.
사용자는 모바일·좁은 desktop 배치를 임시 구현하고 다음 디자인 리뷰에서 확정하도록 승인했다.

## 이유와 trade-off

API/지도키 없이 터치·키보드와 서로 독립된 목록 scroll을 검사할 수 있다.
fixture는 실제 급지·순위·단계·가격·표를 제공하지 않으므로 원본의 데이터 화면 전체와
동일하지 않다. 768px 전환, 시트 높이와 좁은 desktop 검색 재배치는 기술 검토값이다.
이 값들을 제품 최소 viewport/최종 UX로 사용하지 않는다. SVG 경로와 원본 색은 유지하며
원본 색상 대비 제한의 개선은 별도 디자인 승인이 필요하다.

## 재검토 조건

다음 디자인 리뷰에서 responsive 배치를 확정하고 실제 기기 키보드를 확인한다.
지도/API 계약이나 월드컵 SDD가 시작되면 slot 연결과 오류/데이터 상태를 확장한다.
현재 제품 정책은 [앱 화면 틀 결정](../product/specs/app-shell/decisions.md),
기술 구현과 검증은 [앱 화면 틀](../architecture/app-shell.md)를 따른다.
