# ADR-008: 현 계약으로 지도 화면을 연결하고 BE 보완은 명시적인 임시 동작으로 분리한다

> 상태: 적용 · 날짜: 2026-11-15

## 배경

실제 API 읽기 계층은 준비됐지만 화면은 예시 데이터를 사용했다. 사용자는 BE 요청 전달 후
가능한 부분을 기존 화면에 연결하도록 요청했다. 현재 권역 목록에는 면적이 없고 상세 단지에는
좌표가 없어 기존 정책을 모두 만족시키지는 못한다.

## 결정

기존 지도·검색·상세 화면을 실제 API에 연결하고 예시는 별도 route로 분리한다.
초기 급지를 기본으로 표시하고 실제 단지 순위는 서버 기준으로 표시한다.
위치는 상세 bbox의 핀 조회로 보완하되 위치 미확보/실패를 안내하고 임의 좌표를 만들지 않는다.
면적 없는 라벨은 선택 우선·ID 순으로 임시 배치한다. 월드컵 fixture는 실제 화면에 섞지 않는다.

사용자가 승인한 범위는 가능한 부분의 화면 연결이다. 이 임시 정책의 세부 구현은 FE 판단이며
BE 필드나 전체 제품 디자인에 대한 최종 합의를 의미하지 않는다.

## 대안과 trade-off

- BE 보완까지 전체 연결을 기다리는 안은 기존 화면에서 실제 흐름을 검토할 수 없다.
- 전 서비스 핀/모든 상세 경계를 사전 다운로드하는 안은 viewport API 경계를 무너뜨리고 비용이 늘어난다.
- 임의 면적·권역 중심을 넣는 안은 동작처럼 보이지만 정보가 잘못돼 채택하지 않는다.
- bbox 보완은 추가 요청과 누락 가능성이 있으며, ID 우선순위는 원래 면적 우선 UX와 다르다.
  이 제한을 현재 정책·화면 안내·수용 기준에 기록하고 BE 계약 확장 후 재검토한다.

## 재검토

상세 단지 location과 권역 면적이 제공될 때 추가 조회 제거·누락 예외·충돌 우선순위를 검토한다.
민심 전환 UI, 월드컵·상태·랭킹 디자인은 별도 범위다.
실제 SDK+API·물리 기기 검증은 자동/fixture 검증과 독립적으로 수행한다.
