# ADR-005: Figma 토큰과 표시 컴포넌트를 제품 정책에서 분리한다

> 상태: 확정 · 날짜: 2026-10-13 · 영역: 프론트엔드

## 맥락

사용자가 Figma Foundations·Components·Screens를 기준으로 디자인 시스템 기반의
구현 착수를 요청했다. 원본 Foundations는 비어 있지만 파일에 변수·글자·그림자
스타일이 있다. Components는 인스턴스 모음이고 원본은 작업공간에 있다.
급지 색 경계와 Stage 전환 기준은 미정이며 API·SDK·제품 기능 구현은 이번 범위 밖이다.

## 선택지

1. 원본 변수 이름과 primitive→semantic alias를 보존하고 표시 속성을 명시적으로 받는다.
2. HTML 숫자·시안 가정을 바탕으로 정책까지 공통 UI에 내장한다.
3. 외부 UI 라이브러리의 기본 디자인과 색을 사용한다.

## 결정

1을 선택한다. Figma 변수 스냅샷을 CSS로 재생성하고 각 컴포넌트의 native HTML 동작을
유지한다. Grade는 1~5의 시각 variant일 뿐 값 범위 정책이 아니다.
표시 value와 grade는 별도 입력이며 Stage도 횟수 계산 없이 직접 받는다.
접근성 상태·disabled·누락 Pressed·터치 크기는 명시적으로 구현 확장이라 기록한다.
카탈로그는 독립 검토 경로이고 완성된 제품 화면으로 노출하는 흐름을 만들지 않는다.

## 이유와 trade-off

원본 대응이 있어 디자인 수정과 값 검토가 가능하고 아직 확정하지 않은 계산 정책을
프론트 공통 UI가 사실상 고정하지 않는다. native button/input으로 키보드·폼·ref
계약을 유지하며 Radix 등 새 의존성을 이 범위에 추가할 필요가 없다.
표시 전용 구성이라 전체 검색 결과·지도 SDK·패널 상태 연동은 후속 기능에서 작성한다.

Figma 흰 글자 급지 1·4·5와 Primary 색은 일반 텍스트 대비 기준에 못 미친다.
코드 리뷰에서 확인했고 제품 화면 적용 전 디자인 재검토 항목으로 남긴다.
사용자의 Figma 최상위 기준을 지켜 이번에 임의 색 변경을 하지 않았으며,
이를 접근성 대비 준수로 설명하지 않는다. 단순 semantic 이름 도입은 대비를 개선하지 않는다.
터치 hit area·visible focus·ARIA는 구현해도 색상 대비·실제 보조기기 검증을 대체하지 않는다.

## 재검토 조건

Figma의 색상 대비 개선, 토큰·스타일·컴포넌트 변경, 실제 화면 SDD, 모바일 배치·
지원 브라우저 확정, 급지/투표 정책과 API 계약 확정 시 해당 부분을 재검토한다.
현재 원본/코드 대응은 [디자인 시스템 문서](../architecture/design-system.md)를 따른다.
