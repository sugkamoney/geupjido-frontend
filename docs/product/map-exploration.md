# 지도 탐색 표시 단계

> 상태: **제안** · 날짜: 2026-09-20

## 목적

지도에서 넓은 지역을 읽는 흐름과 개별 단지를 탐색하는 흐름을 분리한다.
초기 정식 지원 범위는 데스크톱 웹이며, 모바일 웹의 지원 정책은
[플랫폼 지원 범위](platform-support.md)를 따른다. 표시 기준은 정식 디자인·기획과
실제 데이터 성능 검증 뒤 조정할 수 있다.

## 임시 표시 기준

| NAVER 지도 zoom | 표시 대상 | 동작 |
| --- | --- | --- |
| 0~11 | 권역 | 권역 경계와 권역 정보를 표시한다. 단지 조회는 하지 않는다. |
| 12~13 | 단지 cluster | 현재 화면의 단지 수를 집계한 cluster를 표시한다. |
| 14~21 | 개별 단지 | 현재 화면 범위의 개별 단지 마커를 표시한다. |

Cluster는 개별 단지를 직접 선택하는 대상이 아니며, 사용자를 더 확대된 지도
상태로 유도한다. 사용자가 cluster를 선택하면 지도는 해당 cluster 중심으로 zoom을
2단계 높인다. 이때 단지 목록이나 상세 패널은 열지 않는다. 권역 상세에서 무엇을
우선 표시할지는 기획 확정 전까지 정하지 않는다.

## 보류한 결정

개별 단지 표시 단계에서 한 viewport의 결과가 과도하게 많을 때의 동작은 아직
확정하지 않는다. 확대 안내, cluster 재전환, 별도 목록 등은 실제 단지 분포와
확정 디자인을 검증한 뒤 선택한다. 따라서 이 상황의 API 오류 코드와 화면 문구도
구현 계약에 포함하지 않는다.

## 지도 이동 후 갱신

사용자가 지도 이동이나 확대·축소를 멈춘 뒤 250ms 동안 추가 조작이 없을 때 현재
화면 범위의 단지 데이터를 자동으로 조회한다. 이동 중에는 새 요청을 만들지 않으며,
새 조회가 시작되면 아직 끝나지 않은 이전 조회는 취소한다. 늦게 도착한 이전 결과는
현재 지도 범위와 일치하지 않으면 표시하지 않는다.

## 재검토 조건

다음 검증 결과에 따라 zoom 전환값, cluster 크기와 표시 규칙을 바꿀 수 있다.

- 모바일 지도와 하단 시트의 실제 사용성 검증
- 확정 디자인에서의 지도 정보 밀도와 가독성
- 실제 단지 분포, 지도 렌더링 성능과 API 응답량
- 권역 상세 및 단지 탐색의 최종 사용자 흐름
