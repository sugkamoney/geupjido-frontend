## 미결 결정

| 질문 | 현재 처리 | 다음 검토 시점 |
| --- | --- | --- |
| 급지 범위·5색 경계·단계 기준 | 공급된 표시값만 사용, 자동 산출 없음 | 기획·백엔드 합의 |
| 모바일 최소 viewport/OS 및 시트 높이 | 기존 배치는 검토 가정, 작은 화면 QA 포함 | 디자인 리뷰·실기기 검증 |
| 768~1100 상세/검색 배치 | AppShell 임시 배치 유지 | 좁은 desktop 리뷰 |
| 실제 데이터 과밀·응답 제한 시 사용자 행동 | cluster 정책을 되살리지 않음 | 실제 분포·성능 측정 |
| 면적 단위 | 상세 목록은 MD의 ㎡ 사용 | 후속 대진 화면과 통일 |
| 필터·공유·랭킹/리포트 운영 노출 | 이번 범위에서 제외 | 별도 제품 기획 |
| NAVER 기본 아파트 POI·행정동 라벨 숨김 | SDK 연결 완료. 기본 지도 위에 검토용 라벨·핀을 표시하고 겹침 허용 (2026-10-27 사용자 결정) | 다음 단계에서 Style Editor 스타일 발행·`customStyleId` GL 적용 검토 |
| 작은 모바일 화면의 밀도와 도달성 | 실제 NAVER 줌 기준을 유지한다. 작은 화면에서 압구정은 강남구→청담→압구정 탭 경로로만 닿고, 선택 없는 `권역` 단계는 개요 중심으로 이동 | 디자인 리뷰와 실기기 검증 |
| 선택 핀 이름 라벨의 입력 | 선택 핀 이름은 클릭을 받지 않는다(pointer-events 없음). 핀 몸통으로 선택 | 디자인 리뷰 |
| hover 카드와 고지·NAVER 로고의 겹침 | 카드가 고지·로고 아래에 가려질 수 있음을 알고 있음 | 디자인 리뷰 |
| 라벨과 고지의 읽기 순서 | 고지가 라벨보다 먼저 읽히던 순서가 바뀜(overlay가 지도 입력 요소 안으로 이동) | 접근성 검토 |
| 터치 두 번 탭 확대를 라벨·핀 위에서 시작할 때 | 미검증 | 모바일 실기기 |

미정 투표·표본·단계 임계값을 이 구현으로 확정하지 않는다. API와 지도 연결의 기술적 미확인 사항은 [아키텍처](../../../architecture/map-exploration.md)에 기록한다.

## 리뷰 후 반영

짧은 모바일의 펼친 목록과 접힌 선택 단지 행을 독립적으로 접근할 수 있게 보완했다. 현재 화면 배치는 리뷰 가정이며 최소 viewport·OS 정책은 미결로 유지한다. 최신 공급 표시값을 그대로 사용하며 급지·단계·투표 계산 정책은 추가하지 않았다.
