## 확정 결정

| 결정 | 근거 | 관련 문서 |
| --- | --- | --- |
| 초기 정식 지원과 품질 보증 범위는 데스크톱 웹 | 지도 탐색과 분할 화면은 데스크톱 입력과 화면 크기를 기준으로 설계함 | [플랫폼 지원 범위](../../platform-support.md) |
| 모바일 웹은 접속을 막지 않지만 초기 정식 지원 범위에서는 제외 | 모바일 시나리오와 터치 UX가 아직 정의되지 않음 | [플랫폼 지원 범위](../../platform-support.md) |
| 지도는 시군구·권역·단지 순으로 탐색 | 넓은 범위에서 생활권을 파악한 뒤 단지를 탐색하는 흐름 | [지도 탐색 요구사항](requirements.md) |
| cluster를 선택하면 해당 위치를 중심으로 지도 이동·확대 | 사용자가 묶인 단지를 더 자세히 탐색할 수 있어야 함 | [지도 탐색 요구사항](requirements.md) |
| zoom 0~9, 10~13, 14~21 구분은 현재 표시 기준 | 실제 데이터 수와 브라우저 성능 검증으로 적절성을 확인해야 함 | [지도 API·운영 기준 설계](../../../superpowers/specs/2026-09-19-map-api-and-runtime-design.md) |

## 미결 결정

| 질문 | 현재 상태 | 다음 검토 조건 |
| --- | --- | --- |
| 결과 제한 시 다음 행동은 무엇인가 | 확대 안내, cluster 재전환, 목록 제공 중 미정 | 실제 결과 제한 사례와 화면 디자인을 검토하고 제품 정책 확정 |
| 권역·개별 단지의 상세 정보와 진입 방식은 무엇인가 | 표시 필드와 화면 또는 패널 진입 방식이 미정 | 데이터 계약과 Figma 화면 구성이 확정 |
| 시세·민심 급지는 지도에서 어떻게 노출하고 전환하는가 | 기본 기준과 전환 UI가 미정 | 급지 산출·표본 정책과 화면 디자인이 확정 |
| 지역·평형·연차 필터를 초기 출시에서 제공하는가 | 필터 조합과 기본값이 미정 | 데이터 가용성과 필터 UX가 확정 |
| 통합 검색의 대상과 결과 동작은 무엇인가 | 시군구·권역·단지의 검색 범위와 선택 동작이 미정 | 검색 API 계약과 화면 디자인이 확정 |
| 공유 URL에 어떤 지도 상태를 보존하는가 | 위치·확대 수준·필터·선택 상태의 공개 규칙이 미정 | URL 상태와 개인정보·공유 정책이 확정 |
