# 지도 상태 카드

상태 **설계·QA 초안** · 버전 **v0.2** · 마지막 갱신 **2026-11-27**

지도 탐색 중 현재 기준의 서비스 권역 분포와 민심 집계 상태를 빠르게 확인한다. 범위는 접힌 카드와 펼친 팝오버다. 급지 기준 스위치와 투표함은 배치 및 상태 연동의 기준이며 공개 주간 리포트는 별도 화면과 조회 계약을 사용한다.

## 확인한 근거

- [Figma 핸드오프](https://www.figma.com/design/VB4hekcKLXEAyuFPu4zhVU?node-id=1025-2)의 [카드 안내](https://www.figma.com/design/VB4hekcKLXEAyuFPu4zhVU?node-id=987-1419), [접힘 두 변형](https://www.figma.com/design/VB4hekcKLXEAyuFPu4zhVU?node-id=987-1420), [펼침 두 변형](https://www.figma.com/design/VB4hekcKLXEAyuFPu4zhVU?node-id=987-1468), [데스크톱 세 프레임](https://www.figma.com/design/VB4hekcKLXEAyuFPu4zhVU?node-id=926-2534).
- 백엔드 main에서 확인한 [지도 탭 계약 기록](https://github.com/sugkamoney/geupjido-backend/blob/9371599b8104d949a6471d209f5c22f134e8d010/docs/architecture/map-tab-api.md)과 프런트의 [조회·검증 및 집계 설명](../architecture/map-status-weekly-report-prep.md). 배포 서버 응답은 통합 시 확인한다.

`GET /api/v1/map/status`는 지도 줌·검색 영역과 무관한 서비스 전체 상태다. 참여자와 유효표는 마지막 3시간 발행 집계의 스냅샷이다. 권역별 전환은 유효표 50표, 서로 다른 방문자 10명, 권역 간 유효표 20표를 모두 충족하는 서버 정책을 사용한다. 사용자가 투표해도 카드를 낙관적으로 증가시키지 않으며, 프런트는 지도 목록이나 랭킹 응답으로 전환 여부나 집계 수를 계산하지 않는다.

## 조회 상태와 상호작용 제안

| 상황 | 표시와 동작 |
| --- | --- |
| 최초 조회 중 · 정상 응답 없음 | 기준과 열기 버튼은 유지하고 값 자리에 로딩 상태를 표시한다. 펼쳤을 때도 같은 요청 상태를 표시한다. 숫자·일자를 임의로 넣지 않는다. |
| 정상 응답 · 첫 집계 전 | `lastCompletedAt=null`이면 민심 펼침에 `아직 집계 전이에요`를 표시한다. 참여 0명·유효표 0표와 응답의 전환/수집 권역 수를 표시한다. 초기 분포는 정상 표시한다. 값 0과 로딩·오류를 구분한다. |
| 정상 응답 · 다음 예약 없음 | `nextScheduledAt=null`이면 민심 접힘·펼침에 `예정된 반영 없음`을 표시한다. 첫 집계 전 여부와 독립적으로 처리한다. 디폴트 스케줄을 근거로 다음 시각을 생성하지 않는다. |
| 첫 응답 실패 · 정상 응답 없음 | `지도 상태를 불러오지 못했어요`와 `다시 불러오기`를 제공한다. 자동 재시도 정책은 기존 조회 옵션을 따른다. 명시적 재시도는 상태 조회만 갱신하며 진행 중 중복 실행을 막는다. |
| 마지막 정상 응답 있음 · 갱신 중 | 접힘·펼침에서 동일한 정상 응답을 유지하고 `갱신 중`을 알린다. 처음 로딩 화면으로 되돌리지 않는다. |
| 마지막 정상 응답 있음 · 갱신 실패 | 마지막 정상 값과 집계 시점을 유지한다. `마지막으로 불러온 정보 · 갱신 실패`와 재시도를 제공한다. 예약 시각의 경과는 조회 상태와 별도로 다룬다. |
| 갱신 성공 | 접힘·펼침의 모든 값을 검증된 새 응답으로 함께 갱신하고 오류 안내를 해제한다. |

서버 예약 시각이 지나면 음수 상대 시간을 표시하거나 다음 예약을 추정하지 않는다. 새 응답이 없으면 정상 표시·갱신 중·갱신 실패 모두에서 경과 상태를 알리는 안을 권장한다. 표시 문구와 자동 갱신은 승인 대기다.

기본은 초기 급지 기준의 접힘 상태다. 카드 버튼으로 열고 닫으며 마우스·터치·Enter·Space로 조작한다. 권장 동작은 비모달 팝오버, Escape로 닫고 카드에 초점 복귀, 바깥 클릭으로 닫기다. 바깥의 스위치와 투표함은 원래 동작을 한 번만 실행한다. 스위치 조작으로 바깥 클릭이 발생하면 팝오버를 닫되, 모드 상태와 카드 표시는 함께 바뀐다. 트리거에 `aria-expanded`와 펼친 영역 연결을 제공하며, 재시도 버튼은 카드 트리거 안에 중첩하지 않는다. 카드 내부 클릭·스크롤이 지도 이동이나 선택으로 전달되지 않는지 확인한다.

## 배치와 충돌

- Figma 접힘 카드 256×124는 지도 우측·상단 16, 안쪽 위아래 12·좌우 16, 항목 사이 12, 반경 12, Shadow/Float다. 펼침 440×326은 카드 아래 8, 우측 정렬 권장, 패딩·항목 간격 각각 16·12, 반경 12, Shadow/Float다. 문구 변경이나 짧은 화면에서 고정 높이로 내용이 잘리지 않도록 한다.
- 1920×1080의 03 Screens에서 패널 없음 / 권역 패널 / 랭킹+권역 패널 세 경우 모두 카드 좌상단은 화면 기준 (1648, 16), 투표함은 (1824, 152)다. 투표함 80×80은 접힌 카드 아래 12, 우측 16이고 말풍선은 투표함 왼쪽 12다. 투표함은 월드컵을 연다. 171×44 스위치의 x는 각 907·1099·1294, y는 16으로 가려지지 않은 지도의 중앙을 따라 이동한다. 기준 변경 토스트는 스위치 아래 12에 2.4초 보인다는 안내가 있다.
- 접힌 상태 기준 투표함이 y=152에 남으면 펼친 팝오버의 y=148~474와 겹친다. 펼침 프레임에서 우선순위는 확인되지 않았다. 데스크톱에서는 카드·팝오버·투표함을 한 스택으로 두고 펼친 동안 투표함과 말풍선을 팝오버 아래 12로 내려 접근 가능하게 하는 방안을 권장한다. 짧은 높이에서는 팝오버 본문에 높이 제한과 내부 스크롤을 적용하거나 좁은 화면 대안으로 전환한다.
- 현재 [지도 데이터 알림](../../src/features/map-exploration/map-surface.tsx#L241)은 좌측 `frame.x + 12`, 상단 `frame.y + 72`에 놓인다. [라이브 페이지](../../src/features/map-exploration/live-page.tsx#L114)의 카탈로그·권역·핀 조회 실패, 로딩, 빈 범위를 전달한다. 데스크톱 시안의 우측 카드와 좌측 알림은 위치가 다르나 패널로 가용 폭이 줄면 겹칠 수 있다. 지도 SDK의 중앙 오류·재시도 UI도 별도로 존재한다. 좁은 지도에서 검색 결과, 좌측 알림, 중앙 SDK 오류, 하단 우측 확대 컨트롤이 나타나는 상태를 각각 재현해 충돌을 검사한다. 알림 및 SDK 재시도의 책임을 카드 재시도와 분리한다.
- 768~1100px에서는 권역 상세가 열릴 때 검색 위치가 달라지며, 767px 이하의 현행 셸에는 상단 검색과 하단 내비게이션이 있다. 확인한 상태 카드 시안은 데스크톱이다. 모바일 브라우저는 **배치·상호작용 승인 전 노출 보류**를 권장한다. 모바일 지원이 이번 통합 범위라면 검색과 간섭하지 않는 축약 트리거와 화면 폭 내 스크롤 가능한 시트로 검토한다. 키보드·하단 내비게이션·권역 시트·safe area의 우선순위를 승인받는다. ## 연결 지점

지도 화면에서 기존 [상태 쿼리](../../src/features/map-status/query.ts)를 `useQuery(mapStatusQueryOptions())`로 소비하고, 카드와 팝오버에 같은 결과와 `refetch`를 전달한다. 기준 선택 또는 팝오버 토글을 쿼리 키에 추가하지 않는다. 기준 스위치가 연결되면 현재 기준을 카드 변형에 넘긴다. 현행 지도는 초기 급지 표시를 사용하며 구/권역 레벨 전환으로 민심 기준을 선택할 수 없다. 카드 단독 검증에서는 기준을 테스트 하네스에서 직접 주입한다. 실제 기준 전환 검증은 스위치 통합 후 실행한다. 레이아웃은 [지도 프레임을 받는 지도 화면 조합 지점](../../src/features/map-exploration/exploration-page.tsx#L331)에서 검색·셸과 우측 오버레이의 가용 영역을 맞춘다. `statusContent`는 현재 지도 데이터 알림 슬롯으로 유지한다. 리포트 조회나 주간 스냅샷을 카드 데이터에 섞지 않는다.

## 수용 기준 초안

테스트 환경에서 `/api/v1/map/status`를 가로채 [기존 상태 조회 테스트](../../src/features/map-status/query.test.ts)의 정상 응답을 재사용한다. 조회 시나리오는 테스트 시계를 2026-11-27 14:20 KST로 고정하고 시작한다. 요청 수 검증은 각 시나리오에서 새 세션 또는 쿼리 캐시 초기화 후 시작하고 창 포커스 등 별도 갱신 이벤트를 발생시키지 않는다. 기준 전환·배치의 승인 대기 항목은 아래에 표시한 선행 조건부터 충족한다.
